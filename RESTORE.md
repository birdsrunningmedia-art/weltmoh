# RESTORE.md — New-Device Setup Runbook

## Overview
This document describes the new-device setup flow for the Weltmoh invoicing app.
The app is **offline-first**: local SQLite is the operational database, and Neon Postgres is the durable cloud hub.

## Prerequisites
- Node.js installed
- The `.env.local` file with `NEON_DATABASE_URL` and `SESSION_SECRET` set
- The **sync key** from the original setup (saved in a password manager)

## Steps to Restore on a New Device

### 1. Install and Run
```bash
npm install
# Copy .env.example to .env and fill in SESSION_SECRET and NEON_DATABASE_URL
npm run db:migrate-sqlite
npm run build
npm run start
```

### 2. First-Run Setup
Access `http://localhost:3000/setup` and complete the form:
- Owner name, email, password
- Company name and details
- Invoice prefix (default: `WSNLI-`)
- Starting invoice number (default: `1`)

**IMPORTANT**: After submission, a sync key will be displayed **once**. Copy this key and store it in a password manager. It will never be shown again.

### 3. Login
Access `http://localhost:3000/login` with the Owner credentials.

### 4. Verify Data
All customer, invoice, and business profile data should be loaded from Neon. The Dashboard will show the correct counts.

### 5. Continue Working
The app now operates normally offline-first. Sync state is visible via the sync indicator in the sidebar.

## Sync Key Management
- **Show key**: Only visible during first-run setup. If lost, a new key can be generated by re-running setup after ensuring no data exists in the local DB.
- **Rotate key**: The sync key hash is stored in `sync_state` table. A new key can be generated and the hash updated manually if needed.

## Known Limitations (Deferred to Later Buckets)
- Full PDF/PNG export functionality — see Bucket 3 notes
- Full row sync (push all customer/invoice data to Neon) — see Bucket 4 notes
- Customer payment history (payments dropped for v1 scope)

## Sync now API
The `/api/sync-status` endpoint returns `{ lastSyncAt: "YYYY-MM-DDTHH:MM:SSZ" | null }`.
A `POST` to `/api/sync` triggers the invoice number claiming function.

## Notes
- The app runs fully offline — pulling the network cable does not break invoice creation, viewing, or editing.
- Sync is **one-way** (local → Neon). Neon is the authoritative hub for disaster recovery.
- Invoice numbers are **claimed atomically** on Neon during sync. Two provisional invoices synced back-to-back will never receive the same number.
